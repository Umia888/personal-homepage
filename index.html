01About Me

四件事，一条逻辑

找到真需求 → 排出优先级 → 设计方案 → 推动落地。 这条链路我在电商、社区、法律三个场景里各跑过一遍——行业不同，但判断需求真假、给需求排序、把方案推上线的方法是同一套。

Why

用户不会直接告诉你他要什么

用户只会说「不好用」「没意思」「不像我想要的」。声音大的不等于值得做的——缺的从来不是需求，是判断哪条真值得做。

What

用行为数据找真需求，再排出优先级

从搜索词、互动数据、反馈样本里还原用户实际在做什么，按严重度 / 覆盖面 / 可解决性定级，让「先做哪个」从争论题变成推导题。

How

把判断变成能上线的方案

判断只有变成方案才有价值。我习惯把结论拆成可执行的功能点，和技术、设计、算法对齐口径，跟到上线和复盘——而不是交完一份分析就结束。

🔍
用户洞察与需求判断 主线 从噪音里挑出真需求
+

在小红书负责评估用户反馈的真实性与有效性，并结合当期目标判断优先级。反馈从来不缺，缺的是判断哪条值得做。

⭐ 我的三道筛子

  1. 是不是真问题能不能稳定复现，还是偶发吐槽
  2. 是不是普遍问题影响多少人，还是个例
  3. 做了是否对齐当期目标不对齐的先入池，不占排期

三条缺一都不进排期。需求不能按声音大小投票——喊得最响的往往是最活跃的用户，不是最多的用户。

找需求的三个入口

  • 搜索词拆解 · 看用户实际在找什么
  • 反馈样本研判 · 百人量级
  • 竞品链路盘点 · 别人已经解了哪些

我更信行为数据而不是问卷——搜索是已经发生的真实需求。

📈
数据分析与热点捕捉 看板 · 趋势 · 选题
+

内容侧的判断力来自两头：亲手做过内容并拿到过真实数据；把选题从灵感变成流程。

⭐ 我自己发起的一件事：热点看板

当时选题方向靠人肉刷热点，效率低且不可复现。我做了个自动看板：粘贴链接 → 每 5 小时自动抓取 → 生成登记卡片，含摘要、热度评级、关键词、话题与风险点，按热度分五档排序。它把「灵感」变成了可复用的数据输入——这不是别人派的活，是我发现问题之后自己做的。

🎯
质量标准与优先级 定标准 · 定先后
+

一堆问题摆在面前，凭什么说先做这个？业务侧要的是排序依据，不是问题清单。

先建立用户心理的递进模型

  1. 基础可用不能出硬伤，出了就是废品
  2. 体验达标要明显好过用户自己能得到的
  3. 愿意分享过得了自己这关，才会传播

三层递进且不可跳跃，底层不成立时上层做得再好也没意义。优先级由此自然推导，不需要靠资历或嗓门争论。

再用三轴定级

  • 严重度 · 击穿哪一层
  • 频次 · 抽样中的出现比例
  • 可解决性 · 是能力问题还是执行侧可解

三轴交叉后问题清单会自动收敛成一份可以直接排期的优先级表。好的排序框架，标准是不同角色看完能得出同一个结论。

🛠
方案设计与落地推动 从判断到上线
+

需求判断完不算完。得变成方案、推给对的人、跟到上线。

两端的差别不在方法，在验收标准。C 端看用户愿不愿意用，B 端看流程是不是真的变快了。

模型测评你怎么做？

我会拆成几个维度：人脸一致性、模板契合度、身体比例、画质、稳定性，按维度打分并归因（是 prompt 问题、模型能力问题、还是模板结构问题），再把结论反馈给模型与产品同学，用于判断"能不能上线 / 需不需要再练"。

什么是 Vibe Coding？你怎么理解？

Vibe Coding 就是——不排期，不等资源，把想法用 AI 直接推到可运行的原型。对我来说它是"验证想法的最短路径"，而不是取代工程的手段。

做 Skill / Prompt 有什么心得？

三条：分块打标签 比 "写死大 prompt" 好用；QA 范例 比 "描述规则" 见效快；约束条件 是保底，不是主菜。

可以找你合作什么？

AI 方案咨询、模型测评方法、Prompt / Skill 工程、AIGC 内容制作，以及"把一个想法快速做成能用的原型"这件事。
